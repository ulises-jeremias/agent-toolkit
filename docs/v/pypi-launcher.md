# PyPI thin V launcher

**Issue:** [#535](https://github.com/ulises-jeremias/agent-toolkit/issues/535)  
**ADR:** [ADR-021](../adrs/ADR-021-pypi-binary.md)

Same idea as the npm trampoline (`packages/npm/agent-toolkit-cli/bin/agent-toolkit.js`): `agent-toolkit` / `agent-toolkit-cli` console scripts call `agent_toolkit.launcher:main`, which `exec`s (POSIX) or spawns (Windows) the bundled native binary. **No Python business logic.**

| Script | Implementation |
|--------|----------------|
| `agent-toolkit` | V launcher |
| `agent-toolkit-cli` | V launcher (alias) |

`agent-toolkit-py` was **removed** ([python-fallback.md](python-fallback.md)) — history at `9163c93` (`2026-08-14 chore(pypi): drop Python CLI quarantine; keep npm-style V trampoline`) which deleted 14 `packages/pypi/.../swarm` + 33 `cli/*` files and kept only `hatch_build.py` + `launcher.py` as the trampoline.

## Install channel

```bash
# PyPI launcher channel (ADR-021, wheels since v1.11.0)
uv tool install 'agent-toolkit-cli>=1.11.0'
uvx --from agent-toolkit-cli agent-toolkit doctor
# or
pip install 'agent-toolkit-cli>=1.11.0'
agent-toolkit doctor
```

Wheels are platform-tagged (`manylinux_2_38_*` for Linux, never `linux_x86_64`) and bundle the V binary under `agent_toolkit/bin/agent-toolkit`. See `packages/pypi/agent-toolkit-cli/hatch_build.py` which sets `pure_python = False` when a native file is present so pip will not install a Linux wheel on macOS.

## Resolution order

`AGENT_TOOLKIT_BIN` → `agent_toolkit/bin/agent-toolkit` inside the wheel → `AGENT_TOOLKIT_ROOT/build/agent-toolkit{,-v}`.

- `AGENT_TOOLKIT_BIN` overrides everything (explicit binary path).
- Wheel `agent_toolkit/bin/` is the default for installed consumers.
- `AGENT_TOOLKIT_ROOT=$PWD` fallback resolves `build/agent-toolkit` built by `make.vsh build-cli` (`vcmd('-d commit=${commit} -o ${out} ${join_path(r, "cmd/agent-toolkit")}')` + `cp build/agent-toolkit-v`). Dev usage: `AGENT_TOOLKIT_ROOT=$PWD ./build/agent-toolkit build --check`.

## VMODULES vs embedded_data

`make.vsh` sets `VMODULES=$PWD/modules` so `import agent_toolkit_core` resolves to `modules/agent_toolkit_core/` during `vet`/`test`/`build`. Release binaries embed capabilities via `modules/agent_toolkit_core/embedded_data.v` (`$embed_file` 1647 files, generated by `scripts/generate-embedded-data.vsh` / `make.vsh gen-embedded`). Wheel `agent_toolkit/data/` is an alternate tier: launcher sets `AGENT_TOOLKIT_ROOT` to that `data/` when needed (`bundled_data_root()`), mirroring the embedded path. See `docs/HOW_TO_DEVELOP_V.md` dev flow and `distribution/README.md` adapters.

## Build

```bash
./make.vsh build-cli              # → build/agent-toolkit (+ copy build/agent-toolkit-v)
scripts/prepare-native-bin.sh     # copies build/agent-toolkit into wheel src/agent_toolkit/bin/ before hatch wheel
# Hatch hook packages/pypi/agent-toolkit-cli/hatch_build.py trampolines to V; fallback delegates to AGENT_TOOLKIT_ROOT
```
