## Architecture actually present

- Electron supervises the real V domain server on localhost, dynamic port, health/version/mutation-gate checks. Credentials are passed in environment rather than command argv (`electron/backend.ts:279–290`, main). Keep this boundary and bundled binary resolution.
- Renderer is sandboxed/context-isolated (`electron/main.ts:124–125`). Focus uses typed narrow IPC (`electron/ipc.ts:233–267`), separate from V domain HTTP operations.
- FocusService owns provider processes, turn status, approvals, journal and live deltas (`electron/focus/service.ts:22–26`). Default adapter registry contains **Claude only** (`:59–61`). Installed/authenticated Codex and OpenCode are separately discovered but not supported structured sessions.
- Claude uses the CLI stream protocol and permission control requests, preserves provider session ID for resume, and kills process groups on termination (`electron/focus/claude.ts:45–63,112–142,169–206`). This is useful infrastructure, not a terminal transcript simulation.
- Thread metadata and event journals live at `<workspace>/.agent-toolkit/focus/threads/<id>`; metadata atomic replacement, append-only events, private modes and no-follow checks are implemented (`electron/focus/journal.ts:6–13,34–75,144–166,195–207`). Preserve these IDs and formats through UI changes.
- Crash reconciliation marks orphaned running sessions interrupted and resolves stale approvals (`electron/focus/service.ts:299–322`). App shutdown closes active turns and kills providers (`:249–258`). History persists but ongoing Focus work does **not** survive closing Desktop. Terminal PTY sessions, in contrast, run in a detached host and may survive (`electron/terminal.ts:8–15`). This difference needs clear product language.
- Provider account probes drop email/org data (`electron/focus/providers.ts:8–12`); Claude checks `auth status --json`; Codex checks `login status`; OpenCode checks `auth list` (`:106–153`). An authentication probe does not prove model quota or a successful coding turn. OpenCode currently accepts any nonempty successful auth-list output as ready; tighten that parser before shipping OpenCode sessions.

## Confirmed rescue branch defect

`electron/focus/codex.ts` adds a 549-line app-server adapter, including thread start/resume, streamed messages, tools, file edits, approval handling and interruption. **It is never imported or registered**: repository search finds the class declaration only; `service.ts:59–61` remains Claude-only. Therefore Codex Focus is currently unreachable even in PR #1780. Do not describe this as delivered multi-provider support.

Codex handles command and file approval RPCs (`codex.ts:335–367`) but rejects every other server request (`:368–369`). Interactive user questions / newer permissions requests have no UI. Model capability discovery is available through the adapter but must be tested against installed CLI protocol. Factory registration should follow focused adapter tests and a real disposable-repo task, not precede review blindly.
