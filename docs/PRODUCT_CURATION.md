# Product curation policy — what belongs in which product

> **Authoritative source:** `distributions/products.yaml` + `docs/SKILL_PRODUCT_MATRIX.md` (generated by `scripts/generate-skill-matrix.py`).

## Products

| Product | Purpose | Audience |
|---------|---------|----------|
| `agent-toolkit-core` | Minimal viable — Jira/Confluence agentic triage, lean loops | Teams that want the smallest install |
| `agent-toolkit-forge` | Core + ClickUp + Figma + GitHub/GitLab + Slack + dbt/Snowflake + Playwright | Cross-functional product teams |
| `agent-toolkit-complete` | Forge + agents + all loops + MCP | Power users / workstation |
| `agent-toolkit-agents` | Agent personas only (no skills) | Tool-specific agent browsing |

## Curation rules

1. **Core stays small** — a skill joins `core` only if it is:
   - used in weekly triage by most teams (Jira, Confluence, GitHub),
   - not domain-specific (e.g. dbt/Snowflake are forge+),
   - not experimental (must have stable product+target wiring and `doctor` coverage).

2. **Forge is the default team bundle** — add a skill to `forge` when it:
   - completes a vertical (e.g. delivery: Jira ↔ GitHub ↔ Slack),
   - has at least one internal example or pack referencing it,
   - does not bloat `core` for lean users.

3. **Complete is the superset** — every catalog skill that is not catalog-only appears here.

4. **Catalog-only** — a skill stays catalog-only (installable via `agent-toolkit install --skill <name>` or referenced in `agent-toolkit.yaml`) when it is:
   - niche (e.g. single-domain), or
   - awaiting curation (needs matrix + example before promotion).

5. **Third-party never in products** — external npm / github / url packs (former `ui-ux-pro-max`, JIRA/Confluence external packs) never enter `distributions/products.yaml` or `plugins/`. They live in `agentic-workstation` via `chezmoiexternal` + `skills-external/` (see `docs/CONCEPTS.md` “Third-party boundary” and `agentic-workstation/docs/AGENT_TOOLKIT.md`). This keeps `agent-toolkit` vendor-neutral and avoids supply-chain bloat.

## Process

- Propose membership changes via an issue labeled `product-curation` referencing `docs/SKILL_PRODUCT_MATRIX.md`.
- Keep PRs **small** — one product change per PR (e.g. “feat(product): add dbt to forge”).
- Update the matrix via `python3 scripts/generate-skill-matrix.py` and include the diff.
- Link the example or pack that motivates the promotion.
